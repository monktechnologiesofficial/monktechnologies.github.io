## Notes for Writing
- Start with the problem: what can't traditional databases do well that vector databases solve?
- Build intuition: use analogies (semantic similarity like "distance" in meaning space)
- Explain embeddings first: vector databases are useless without understanding embeddings
- Clarify the paradigm shift: exact match → similarity search
- Practical focus: connect concepts to real AI applications (RAG, agents, recommendations)
- When to use: not every application needs a vector database; provide decision criteria
- Product overview: mention popular options (Chroma, Pinecone, Weaviate, etc.) fairly without heavy bias
- Simple example: show basic usage pattern without overwhelming setup
- Career angle: this is essential knowledge for AI engineering roles

## Key Data Points to Include
- What problem vector databases solve: semantic/similarity search at scale
- Key difference from traditional databases: similarity search vs. exact match
- Core technology: embeddings (vectors), approximate nearest neighbor (ANN) algorithms
- Primary use cases: RAG, semantic search, recommendations, image search
- Popular products: Chroma (simple, open-source), Pinecone (managed, scalable), Weaviate (open-source, feature-rich), Milvus (scalable, open-source), Qdrant (Rust-based, fast)
- When you need one: applications requiring semantic search, working with unstructured data (text, images), building RAG systems
- When you don't: simple CRUD apps, exact match queries, small datasets (< 10k items)
- Getting started: Chroma is easiest for learning, takes ~10 lines of code
